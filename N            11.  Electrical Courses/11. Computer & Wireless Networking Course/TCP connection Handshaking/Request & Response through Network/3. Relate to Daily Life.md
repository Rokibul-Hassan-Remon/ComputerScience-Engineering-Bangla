HTTP আর TCP কি?  
HTTP হচ্ছে নেটওয়ার্কের রাস্তা ।। যেমন মহাখালী থেকে গুলশান যেতে হলে কোন রাস্তায় যেতে হবে আবার মোহাম্মদপুর গেলে কোন দিকে যেতে হবে এটা ঠিক করে দেয় http  
  
আর TCP হলো সেই রাস্তায় চলা কুরিয়ার সার্ভিসের ট্রাক 🚚। এই ট্রাকের কাজ শুধু মাল পৌঁছানো না, বরং সঠিক অর্ডারে, ঠিকঠাকভাবে মাল পৌঁছে দেওয়া। TCP খুবই স্ট্রিক।  
Sender-কে সে গ্যারান্টি দেয় -  
- তুমি যে ডাটা পাঠাবে  
- যেই অর্ডারে পাঠাবে  
- ঠিক সেই অর্ডারেই রিসিভারের কাছে পৌঁছাবে  
  
ধরা যাক, রাস্তার কোথাও সমস্যা হলো (ড্যামেজ রাউটার, বাজে ক্যাবল ইত্যাদি)  
এক বস্তা চাল (একটা data packet) পড়ে হারিয়ে গেল।  
  
👉 তখন TCP কী করবে?  
সে Sender-কে জানাবে -  
“এই প্যাকেটটা হারিয়ে গেছে, আবার পাঠাও।”  
  
এটাই packet loss handling।  
  
যদি ডাটা A, B, C এই অর্ডারে পাঠানো হয়  
কিন্তু মাঝপথে B দেরি করে  
  
তাহলে TCP বলবে:  
👉 “C, তুমি ওয়েটিং রুমে (buffer) বসো।  
B আগে আসুক, তারপর তোমার সিরিয়াল।”  
কারণ TCP-তে অর্ডার ভাঙা চলবে না।  
  
TCP কানেকশন তৈরি হয় 3-way handshake দিয়ে  
SYN = Synchronize  
SYN-ACK = Synchronize + Acknowledge  
ACK = Acknowledge  
  
Client → Server: SYN ( আমি তোমার সাথে সম্পর্ক স্থাপন করিতে চাই)  
Server → Client: SYN-ACK ( আমি তোমার লেটারটি পেয়েছি। আমিও রাজি)  
Client → Server: ACK ( ওকে ধন্যবাদ। আমি তোমার রেসপন্স পেয়েছি)  
  
অলাইন থেকে সফটওয়র ডাউনলোড অথবা সফট্যার আপডেট এসব ক্ষেত্রে TCP কানেকশন ইম্পরট্যান্ট। কারণ যদি ডাটা সিকুয়েন্স ভেঙে আসে বা মাঝখানে লস হয় তাহলে সফটওয়্যার ক্র্যাশ করবে।
