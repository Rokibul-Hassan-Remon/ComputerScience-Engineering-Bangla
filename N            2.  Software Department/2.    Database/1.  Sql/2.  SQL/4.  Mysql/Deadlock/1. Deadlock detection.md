**MySQL**-এর ভেতরে আসলে **lock-এর আলাদা আলাদা ধরন** আছে।  
যেমন—

- **S lock (Shared lock)**
    
- **X lock (Exclusive lock)**
    

আমরা এখানে যেটা নিয়ে কথা বলছি, সেটা হলো **Exclusive lock (X lock)**।

**Exclusive lock** মানে হলো—  
একবার আমি কোনো **row-এর ওপর lock** নিয়ে নিলে, সেই **transaction commit** না হওয়া পর্যন্ত:

- শুধু আমিই ওই row-টা **modify** করতে পারব
    
- বা ওই row-টা **use** করতে পারব
    

অন্য কেউ পারবে না।

অন্যদিকে, **Shared lock** সাধারণত **reading-এর জন্য** ব্যবহার করা হয়।

---


### **1️⃣ MySQL Deadlock Detection**

- MySQL **Inno DB** engine deadlock detect করে **automatic lock wait graph** maintain করে।
    
- যখন **transaction A** একটি row lock করছে এবং **transaction B** অন্য row lock করছে, এবং তারা একে অপরের lock চাইছে → circular wait তৈরি হয়।
    
- Inno DB তখন **deadlock detect করে এবং error 1213 (ER_LOCK_DEADLOCK) return করে।**
    

---

### **2️⃣ Deadlock Victim (কাকে kill করা হয়)**

- Deadlock break করার জন্য DB engine একটি **“victim transaction”** choose করে।
    
- Criteria:
    
    1. কম resource consume করা।
        
    2. কম modification impact।
        
- Victim transaction **rollback** করা হয়, আর অন্য transaction চলতে থাকে।
    

> সহজভাবে: **“যে transaction rollback করলে কম ক্ষতি হবে, সেটাকে kill করে deadlock ভেঙে দেয়।”**

---

### **3️⃣ Deadlock Prevention Techniques**

1. **Access resources in the same order**
    
    - সব transaction একই order-এ tables/rows access করবে → circular wait কমে।
        
2. **Keep transactions short**
    
    - কম সময় ধরে locks ধরে রাখা → wait কম হয়।
        
3. **Use lower isolation levels when possible**
    
    - Serializable না করে, Read Committed / Repeatable Read → lock contention কমে।
        
4. **Explicit lock timeout / retry logic**
    
    - Lock না পাওয়া গেলে wait না করে transaction retry করতে পারে।

```mysql
Step 1: Start Transactions
--------------------------------
T1 locks Row A       T2 locks Row B
   |                     |
Step 2: Wait for each other
--------------------------------
T1 wants Row B → wait
T2 wants Row A → wait
   |                     |
Step 3: Deadlock Detected
--------------------------------
MySQL detects circular wait → chooses T1 as victim
   |
Step 4: Resolution
--------------------------------
T1 rollback
T2 continues

```
