## 🔐 Scenario 1 — Authentication (JWT)

**Scenario:** Publisher wants secure API. Users can register, login, refresh tokens, logout.

**Question:** কোন endpoints আর flows দরকার? কি DTO এবং minimal controller code হবে?

**Hint:**

- Use JWT access token (short lived) + refresh token (long lived).
    
- Endpoints: register, login, refresh, logout.
    
- Store refresh tokens server-side (DB) or use revocation list.
    

**Solution (concise):**

### Endpoints
```cs
POST /api/v1/auth/register
POST /api/v1/auth/login
POST /api/v1/auth/refresh
POST /api/v1/auth/logout

```

**DTOs (examples)**
```cs
public class RegisterDto { public string Email {get;set;} public string Password {get;set;} public string FullName {get;set;} }
public class LoginDto { public string Email {get;set;} public string Password {get;set;} }
public class AuthResponseDto { public string AccessToken {get;set;} public string RefreshToken {get;set;} public DateTime ExpiresAt {get;set;} }
public class RefreshRequest { public string RefreshToken { get; set; } }

```

**Minimal Controller Sketch**
```cs
[ApiController]
[Route("api/v{version:apiVersion}/auth")]
[ApiVersion("1.0")]
public class AuthController : ControllerBase
{
    [HttpPost("register")]
    public async Task<IActionResult> Register([FromBody] RegisterDto dto) { /* create user, hash pw */ }

    [HttpPost("login")]
    public async Task<IActionResult> Login([FromBody] LoginDto dto) {
        // validate credentials
        // create access token (JWT) and refresh token (GUID)
        // save refresh token (UserId, token, expiry, device info)
        // return AuthResponseDto
    }

    [HttpPost("refresh")]
    public async Task<IActionResult> Refresh([FromBody] RefreshRequest req) {
        // validate refresh token from DB, issue new access + refresh (rotate)
    }

    [HttpPost("logout")]
    public async Task<IActionResult> Logout([FromBody] RefreshRequest req) {
        // revoke refresh token (delete/mark revoked)
    }
}

```

### JWT creation (sketch)

- Claims: sub(userId), email, role(s), iat, exp
    
- Sign with symmetric key (HMACSHA256) stored in config (appsettings).
    
- Access token short (5–15 min), refresh token long (7–30 days).

## 🔐 Scenario 2 — Authorization (roles & policies)

**Question:** কিভাবে role-based ও policy-based authorization apply করব?

**Hint:**

- Roles: `Admin`, `Publisher`, `User`
    
- Policy example: require claim `department: editorial`
    

**Solution (concise):**

- Add roles to user (Identity or custom).
    
- Protect endpoints:
```cs
[Authorize(Roles = "Admin,Publisher")]
[HttpPost("books")]
public IActionResult CreateBook(...)
{

}

[Authorize(Policy = "EditorialOnly")]
[HttpDelete("books/{id}")]
public IActionResult DeleteBook(int id)
{

}

```

- Policy registration (Startup):
```cs
services.AddAuthorization(options => {
   options.AddPolicy("EditorialOnly", p => p.RequireClaim("department", "editorial"));
});

```

## 🔁 Scenario 3 — Versioning

**Question:** API versioning কিভাবে করবে?

**Hint:** Use route versioning `api/v1/...` and header or query if needed.

**Solution:**

- Configure:
```cs
services.AddApiVersioning(options => {
  options.DefaultApiVersion = new ApiVersion(1,0);
  options.AssumeDefaultVersionWhenUnspecified = true;
  options.ReportApiVersions = true;
});

```

- Controller route: `[Route("api/v{version:apiVersion}/books")]`
    
- Maintain v2 controller if you change contract.

## 🔗 Scenario 4 — HATEOAS (resource links)

**Question:** কীভাবে response-এ links যোগ করবে?

**Hint:** Provide self, update, delete links conditionally (based on auth).

**Solution (example response for single book):**
```cs
{
  "bookId": 1,
  "title": "Advanced C#",
  "price": 600,
  "links": 
	[
	    { "rel": "self", "href": "/api/v1/books/1", "method": "GET" },
	    { "rel": "update", "href": "/api/v1/books/1", "method": "PATCH" },
	    { "rel": "reviews", "href": "/api/v1/books/1/reviews", "method": "GET" }
    ]
}

```

- In controller, build links using `Url.Action` and include only allowed actions per user.

## ⚠️ Scenario 5 — Error handling & unified response

**Question:** কীভাবে consistent error responses রাখবে?

**Hint:** Use middleware to catch exceptions + return standard shaped error.

**Solution:**

- Global error middleware:
```css
app.UseMiddleware<ErrorHandlingMiddleware>();

```
- Error response shape:
```cs
{
  "success": false,
  "errors": [
    { "code": "BOOK_NOT_FOUND", "message": "Book not found", "field": "bookId" }
  ],
  "traceId": "..."
}

```

- For model validation use `BadRequest(new { errors = ModelState })`.

## 🔁 Scenario 6 — DTO mapping (AutoMapper)

**Question:** কিভাবে domain models থেকে DTO map করবে?

**Hint:** Use AutoMapper profiles to separate domain and API contracts.

**Solution (sketch):**
```cs
public class BookProfile : Profile {
  public BookProfile() {
     CreateMap<Book, BookDto>();
     CreateMap<CreateBookDto, Book>();
  }
}

```

- Register: `services.AddAutoMapper(typeof(Startup));`
    
- Controller uses `_mapper.Map<BookDto>(book)`.

## 📁 Scenario 7 — Folder / Project Structure (recommended)
```cs
/src
  /Api          -> Controllers, DTOs, Filters
  /App          -> Services (business logic), interfaces
  /Domain       -> Entities, ValueObjects
  /Infrastructure -> EF Core DbContext, Repositories, Migrations, External integrations
  /Tests

```

- Controllers keep thin, call App services.
    
- Services contain business logic; repositories for DB access.
    
- DTOs live near Controllers (Api layer) or in `/Api/DTOs`.

## ✅ Exam-Ready Minimal Example (Putting pieces together)

### appsettings.json (JWT)
```cs
"Jwt": {
  "Key": "VERY_SECRET_KEY_ChangeInProd",
  "Issuer": "MyApi",
  "Audience": "MyApiClient",
  "AccessTokenMinutes": 15,
  "RefreshTokenDays": 7
}

```
Startup (essentials)
```cs
services.AddAuthentication(options => {
  options.DefaultAuthenticateScheme = JwtBearerDefaults.AuthenticationScheme;
  options.DefaultChallengeScheme = JwtBearerDefaults.AuthenticationScheme;
})
.AddJwtBearer(opts => {
  opts.TokenValidationParameters = new TokenValidationParameters {
    ValidateIssuerSigningKey = true,
    IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(cfg["Jwt:Key"])),
    ValidateIssuer = true,
    ValidIssuer = cfg["Jwt:Issuer"],
    ValidateAudience = true,
    ValidAudience = cfg["Jwt:Audience"],
    ValidateLifetime = true
  };
});
services.AddAuthorization();
services.AddApiVersioning(...);
services.AddAutoMapper(...);

```
