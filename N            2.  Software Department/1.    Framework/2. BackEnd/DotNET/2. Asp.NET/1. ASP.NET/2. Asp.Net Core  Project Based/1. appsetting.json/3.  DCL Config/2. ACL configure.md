# 1️⃣ Real-World Architecture (High Level → Exact)

ধরি আমাদের project নাম: **EmployeeApp**

### Database: `EmployeeDb`

আমাদের DB-তে ৩টা user থাকবে 👇

|User|কে|কী কাজ|
|---|---|---|
|**admin**|DBA|CREATE / DROP / ALTER|
|**developer**|Dev phase|Migration, seed|
|**app_user**|Runtime App|SELECT / INSERT / UPDATE|

👉 **সবচেয়ে important:**  
❌ Runtime app কখনোই admin বা developer user ব্যবহার করবে না

# 2️⃣ SQL Server Implementation (Exact Commands)

## 🔹 Step 1: Admin / DBA user

(Usually already exists, e.g. `sa`)

`Role: DBA Permission: FULL Used by: DBA only`

---

## 🔹 Step 2: Developer user (Migration / Dev phase)

```sql
CREATE LOGIN dev_user WITH PASSWORD = 'Dev@12345';
GO

USE EmployeeDb;
CREATE USER dev_user FOR LOGIN dev_user;
GO

-- Give schema change permission
GRANT CREATE TABLE TO dev_user;
GRANT ALTER TO dev_user;
GRANT DROP TO dev_user;

```

📌 এই user:

- EF Migration চালাবে
    
- Table / Column add করবে
    
- Dev / Staging-এ ব্যবহার হবে
    

---

## 🔹 Step 3: Runtime Application user (Most restricted)

```sql 
CREATE LOGIN app_user WITH PASSWORD = 'App@12345';
GO

USE EmployeeDb;
CREATE USER app_user FOR LOGIN app_user;
GO

-- Only DML permission
GRANT SELECT, INSERT, UPDATE ON dbo.Employees TO app_user;

```


❌ Notice:

- CREATE নেই
    
- DROP নেই
    
- ALTER নেই
    

---

# 3️⃣ ASP.NET Core Project Setup (Very Important)

## 🔹 appsettings.json
```sql
{
  "ConnectionStrings": {
    "RuntimeConnection": "Server=.;Database=EmployeeDb;User Id=app_user;Password=App@12345;",
    "MigrationConnection": "Server=.;Database=EmployeeDb;User Id=dev_user;Password=Dev@12345;"
  }
}

```

---

## 🔹 DbContext
```cs
public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options)
        : base(options) { }

    public DbSet<Employee> Employees { get; set; }
}

```

---

## 🔹 Program.cs (Runtime)

```cs
builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlServer(
        builder.Configuration.GetConnectionString("RuntimeConnection")
    ));

```

📌 **Production run করলে শুধু `RuntimeConnection`**

# 4️⃣ Developer Phase (Exact Working)

### ✔ Migration create (Developer machine)

```cs 
	dotnet ef migrations add InitialCreate
```

### ✔ Migration apply (using developer user)
```cs
dotnet ef database update \
  --connection "Server=.;Database=EmployeeDb;User Id=dev_user;Password=Dev@12345;"

```

📌 এখানে:

- dev_user → table create করবে
    
- app_user → involved না

# 5️⃣ Runtime Phase (Exact Working)

User hits API:

```http
POST /employees
```

ASP.NET Core flow:

```cs
HTTP Request
   ↓
DTO Validation
   ↓
EF Core (Parameterized Query)
   ↓
app_user (DML only)
   ↓
SQL Server

```

❌ কেউ যদি inject করে:

```cs
DROP TABLE Employees
```

👉 SQL Server বলবে:

```cs
The DROP permission was denied
```


🎯 **Database saved itself**

# 6️⃣ Developer vs Admin vs App User (Clear Mental Model)
```cs
ADMIN (DBA)
 └── controls schema & security

DEVELOPER
 └── changes schema via migration

APPLICATION
 └── only reads/writes data

```

---
#  Advanced option for DBA
## তাহলে আমরা `sa` কেন ব্যবহার করছি না app-এ?

কারণ 👇

> ❌ `sa` দিয়ে application চালানো = security disaster

যদি:

- SQL Injection হয়
    
- Credential leak হয়
    

👉 পুরো server compromise হয়ে যাবে

তাই real world-এ:

- `sa` **only DBA use করে**
    
- App / developer কখনো `sa` use করে না
    

---

## 🔹 Real-World Setup কেমন হয়?

### Production SQL Server-এ সাধারণত:

|User|কে ব্যবহার করে|কেন|
|---|---|---|
|`sa` বা sysadmin|DBA|Server control|
|`db_owner` role user|DBA / Ops|Schema management|
|`dev_user`|Developer|Migration|
|`app_user`|Application|Runtime|

---

## 🔹 Why “usually already exists”?

কারণ:

- SQL Server install করলে `sa` থাকেই
    
- আলাদা করে DBA user বানানো লাগেও না  
    (though best practice হলো `sa` disable করে অন্য DBA user বানানো)
    

---

## 🔹 Best Practice (Important)

### ✔ Production-এ কী করা হয়:

- `sa` disable করা হয়
    
- DBA-র জন্য আলাদা admin user বানানো হয়
    

```sql
CREATE LOGIN dba_admin WITH PASSWORD = 'Strong@Admin123';
ALTER SERVER ROLE sysadmin ADD MEMBER dba_admin;
```

---

## 🔹 So, simple language-এ বললে

> **“Admin / DBA user” মানে হলো SQL Server-এর সেই account  
> যেটার কাছে সব permission আছে।  
> সাধারণত সেটা `sa`, কিন্তু real production-এ DBAরা আলাদা admin account ব্যবহার করে।**

---

# 🔥 Important Rule (Never Break This)

> ❌ Never allow runtime app to CREATE / DROP tables  
> ✅ Schema change ≠ application logic
