## 🎯 Lesson 2: Heap Generations – কীভাবে কাজ করে, আর কেন লাগে

### 🧩 1. কেন .NET heap কে generation-এ ভাগ করে?

Microsoft Docs বলে 👇

> “To optimise garbage collection performance, the managed heap is divided into generations: 0, 1, and 2.”  
> — [Microsoft Learn: Automatic memory management](https://learn.microsoft.com/en-us/dotnet/standard/automatic-memory-management?utm_source=chatgpt.com)

**মানে:**  
GC (Garbage Collector) যদি প্রতি বার পুরো heap স্ক্যান করতো, performance খুব slow হয়ে যেত।  
তাই runtime object-গুলিকে বয়স (lifetime) অনুযায়ী ভাগ করে:

- নতুন object → Gen 0
    
- মাঝারি বয়স → Gen 1
    
- দীর্ঘমেয়াদি → Gen 2
    

এতে করে GC অনেক দ্রুত কাজ করতে পারে, কারণ Gen 0-এর collection খুব ছোট অংশ নিয়েই কাজ করে।

---

### 🧱 2. তিনটা Generation কিভাবে কাজ করে

|Generation|কী রাখে|কখন collect হয়|Behaviour|
|---|---|---|---|
|**Gen 0**|সদ্য তৈরি object (short-lived)|সবচেয়ে ঘন ঘন|দ্রুত collect হয়|
|**Gen 1**|Gen 0 থেকে বেঁচে থাকা object|মাঝেমাঝে|transitional buffer|
|**Gen 2**|দীর্ঘমেয়াদি object (যেমন static data, cache)|খুব কম|large/full GC তে collect হয়|

📘 **Doc Reference:**

> “Objects that survive collections are promoted to a higher generation and collected less frequently.”  
> — [Microsoft Learn: Garbage Collection Fundamentals](https://learn.microsoft.com/en-us/dotnet/standard/garbage-collection/fundamentals?utm_source=chatgpt.com)

---

### ⚙️ 3. Promotion কীভাবে হয় (object upgrade system)

ধরা যাক, তোমার প্রোগ্রামে `Customer` নামের একটা object তৈরি হলো।

1. যখন তৈরি হলে সেটা **Gen 0** তে যায়।
    
2. যদি প্রথম GC তে এখনও জীবিত থাকে (মানে reference আছে), সেটা **Gen 1** এ “promote” হয়।
    
3. পরেরবারও যদি টিকে থাকে, তখন সেটা **Gen 2** তে যায়।
    
4. Gen 2 এ গেলে সেটা অনেকদিন বেঁচে থাকে (only full GC can collect it)।
    

💡 **Microsoft Docs quote:**

> “Objects that survive a generation 0 collection are promoted to generation 1, and so on.”  
> — [learn.microsoft.com/dotnet/standard/garbage-collection/fundamentals](https://learn.microsoft.com/en-us/dotnet/standard/garbage-collection/fundamentals?utm_source=chatgpt.com)

### 🧠 4. কেন এটা পারফরম্যান্সে huge impact আনে?

কারণ research অনুযায়ী:

> “Most objects die young.” — অর্থাৎ অধিকাংশ object খুব অল্প সময়েই দরকার ফুরিয়ে যায়।

তাই GC যদি শুধু নতুন object (Gen 0) collect করে, তাহলে memory efficiently clean হয়, আর পুরনো stable object-গুলিতে হাত দেয় না — performance বাড়ে।

---

### 🧩 5. Large Object Heap (LOH) – আলাদা segment

Microsoft Docs অনুযায়ী:

> “Objects greater than 85,000 bytes are stored in the Large Object Heap (LOH).”  
> — [learn.microsoft.com/dotnet/standard/garbage-collection/large-object-heap](https://learn.microsoft.com/en-us/dotnet/standard/garbage-collection/large-object-heap?utm_source=chatgpt.com)

- LOH আলাদা হয় কারণ বড় object গুলোকে ঘন ঘন move করা (compaction) ব্যয়বহুল।
    
- LOH সাধারণত Gen 2 এর সাথে collect হয়।
    
- LOH-এর fragmentation কমানোর জন্য .NET 5+ এ **compacting LOH** introduce করা হয়েছে।
    

---

### 🧩 6. Collection Type: Ephemeral vs Full GC

|Type|Covers|Triggers|
|---|---|---|
|**Ephemeral GC**|শুধুমাত্র Gen 0 এবং Gen 1|ছোট allocation pressure এ|
|**Full GC**|Gen 0, 1, 2 এবং LOH সব|বড় memory pressure বা manual call (যেমন `GC.Collect()`) এ|

**Doc reference:**

> “Ephemeral collections occur more frequently and reclaim short-lived objects; full collections reclaim all generations.”  
> — [Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/standard/garbage-collection/fundamentals?utm_source=chatgpt.com)
