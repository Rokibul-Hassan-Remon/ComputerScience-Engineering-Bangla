## 🎯 আজকের লক্ষ্য (Lesson 1):

**“.NET এ memory কিভাবে manage হয় — CLR, managed heap, garbage collection (GC) কীভাবে কাজ করে”**

---

### 🧩 1. প্রথমে: .NET runtime এ memory management কাকে বলে?

Microsoft-এর অফিসিয়াল documentation অনুযায়ী,

> **.NET memory management = automatic allocation + release of memory (via Garbage Collector)**

মানে, .NET-এ যখন তুমি কোনও object তৈরি করো (যেমন `new MyClass()`), তখন CLR (Common Language Runtime) **heap থেকে memory allocate করে** দেয়।  
আর যখন সেই object আর ব্যবহার হচ্ছে না, তখন **GC (Garbage Collector)** সেটা **free করে দেয়**।  
👉 তোমাকে manually `free()` বা `delete` দিতে হয় না — যেমনটা C/C++ এ দিতে হয়।

---

### 🧱 2. .NET মেমরি ২ ভাগে ভাগ হয়:

|Type|Description|
|---|---|
|**Stack**|ছোট ছোট data (যেমন local variables, method call info) রাখে। খুব দ্রুত allocate/deallocate হয়।|
|**Managed Heap**|বড় object বা reference type data রাখে (যেমন class object, array, etc)। GC এটা manage করে।|

📘 Stack হচ্ছে “automatic memory”  
📗 Heap হচ্ছে “managed memory”

---

### 🧩 3. CLR কী করে?

CLR (.NET এর runtime engine) এর কাজ হলো —

1. তোমার code চালানো
    
2. memory allocate/deallocate করা
    
3. garbage collector চালানো
    
4. performance optimise করা
    

**C++ compiler** program-run এর আগে static segment বানিয়ে দেয়।  
**CLR** program চলার সময় dynamically memory allocate করে — তাই .NET এ static/data segment লাগে না।

---

### ♻️ 4. Garbage Collector (GC) কীভাবে কাজ করে

Microsoft Docs থেকে মূল ধারণা👇

GC মূলত managed heap কে পর্যবেক্ষণ করে।  
যখন heap-এ জায়গা কমে আসে, GC খুঁজে বের করে কোন object-গুলো **আর reference নেই (unreachable)**।  
তারপর সেই object-গুলোর memory reclaim (ফিরিয়ে নেয়) করে দেয়।

**Steps:**

1. GC checks all active objects (যেগুলো এখনো reference আছে)।
    
2. Unused objects খুঁজে পায়।
    
3. সেগুলোর memory free করে দেয়।
    
4. Memory compact করে যাতে নতুন allocation efficient হয়।
    

এভাবে memory leak বা dangling pointer-এর ঝামেলা থাকে না।

---

### 🔢 5. Heap Generation System (Important for advanced concept)

.NET-এর heap ৩টা **generation** এ ভাগ করা থাকে:

|Generation|Purpose|
|---|---|
|**Gen 0**|New objects তৈরি হয় এখানে। ছোট ও স্বল্পমেয়াদী object।|
|**Gen 1**|Temporary transition stage; মাঝারি lifetime object।|
|**Gen 2**|Long-lived objects (যেমন static/global data, cached data)।|

💡 GC সাধারণত **Gen 0** প্রথমে clean করে কারণ ছোট object-গুলো দ্রুত মারা যায়। এতে efficiency বাড়ে।

---

### ⚙️ 6. Large Object Heap (LOH)

যখন object খুব বড় হয় (85,000 bytes বা তার বেশি), সেটা **Large Object Heap (LOH)** এ যায়।  
এই heap আলাদা কারণ বড় object গুলোকে GC ঘন ঘন move করে না (memory fragmentation কমানোর জন্য)।

---

### 🧠 7. কেন .NET-এ “data segment” নেই?

কারণ:

- CLR সব object runtime-এ heap-এ allocate করে।
    
- Static/global field-ও heap-এ থাকে।
    
- তাই compiler-defined `.data`, `.bss`, `.code` segment লাগে না।
    
- Memory model purely managed — runtime dynamically handle করে।
    

---

### 🔚 Summary (Microsoft Docs অনুযায়ী সহজ recap):

|Concept|C/C++|.NET|
|---|---|---|
|Memory segment|Fixed: Code, Stack, Heap, Data, BSS|Not fixed, managed dynamically|
|Allocation|Manual (`malloc/new`)|Automatic (`new` under CLR)|
|Deallocation|Manual (`free/delete`)|Automatic (Garbage Collector)|
|Responsibility|Developer|CLR Runtime|
|Safety|Low (dangling pointer possible)|High (GC prevents leaks)|
