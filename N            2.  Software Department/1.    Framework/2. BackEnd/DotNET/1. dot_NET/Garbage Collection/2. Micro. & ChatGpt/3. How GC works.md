## 🧠 1. Garbage Collector-এর কাজ আসলে কী?

**GC-এর কাজ:**  
1️⃣ Unused (unreachable) object খুঁজে বের করা  
2️⃣ সেগুলোর memory ফাঁকা করা  
3️⃣ Heap গুছিয়ে আনা যাতে future allocation সহজ হয়

Microsoft Docs এ বলা আছে 👇

> “The garbage collector's primary job is to reclaim memory occupied by objects that are no longer accessible by the application.”

---

## ⚙️ 2. GC Trigger হয় কবে?

Microsoft Docs অনুযায়ী, GC সাধারণত এই তিন পরিস্থিতিতে চলে:

1. System-এর কাছে heap-এ **space কমে আসে**
    
2. System **low memory signal** পায় (OS থেকে)
    
3. তুমি manually `GC.Collect()` ডাকো (যদিও এটা discourage করা হয়)
    

---

## 🧩 3. GC-এর তিনটি মূল ফেজ (Mark → Sweep → Compact)

### 🧮 (1) Mark Phase

> “The GC identifies which objects are still in use (reachable) and marks them.” — Microsoft Docs

👉 কী ঘটে:

- GC “root references” (যেমন local variables, static fields, CPU registers) থেকে traversal শুরু করে
    
- যে object গুলো এখনো reachable, সেগুলো **marked as alive**
    
- অন্য সব unmarked object = dead
    

📊 Visual Concept:
```css
[Root]
  │
  ├── Object A (alive)
  │     └── Object B (alive)
  └── Object C (dead ❌)

```
### 🧹 (2) Sweep Phase

> “The GC scans the heap for objects that are not marked and reclaims their memory.”

👉 মানে, যেসব object mark phase-এ unmarked ছিল, তাদের memory ফাঁকা করে দেয়।  
এগুলো মুছে ফেলার পর heap-এ ফাঁকা জায়গা তৈরি হয় (holes)।

📊 Concept:
```css
[ A ][ B ][   ][   ][ D ]
          ↑ free space

```
### 🧩 (3) Compact Phase

> “The GC compacts the remaining live objects to reduce fragmentation and to make future allocations faster.”

👉 এখানে GC বেঁচে থাকা object-গুলিকে একসাথে সরিয়ে দেয় যাতে heap-এর ফাঁকা জায়গা একটানা হয়।  
এতে পরবর্তী allocation সহজ ও দ্রুত হয়।

📊 Concept:
```css
Before: [ A ][ B ][   ][   ][ D ]
After:  [ A ][ B ][ D ][   ][   ]

```

## ⚡ 4. Why “Compaction” is important

C/C++ এর heap fragmentation সমস্যা হয় কারণ object-গুলো random জায়গায় allocate/free হয়।  
.NET GC compact করে রাখে, তাই **heap fragmentation কমে যায়**।  
এই কারণেই .NET এ performance stabler থাকে long-running apps এ।

---

## 🔄 5. Phases Summary Table

|Phase|কাজ|Output|
|---|---|---|
|**Mark**|Live object চিনে ফেলা|Marked reachable objects|
|**Sweep**|Dead object সরানো|Free memory space|
|**Compact**|Live object গুছিয়ে আনা|Continuous free space|

---

## 💡 6. Ephemeral vs Full GC (Review)

|Type|Generations Covered|Description|
|---|---|---|
|**Ephemeral GC**|Gen 0 & 1|দ্রুত চলে, ছোট scope|
|**Full GC**|Gen 0, 1, 2, LOH|সম্পূর্ণ heap clean করে|

Full GC সাধারণত বড় memory pressure বা manual call এর সময় হয়।

---

## 🧩 7. .NET GC Algorithm Type

Microsoft Docs অনুযায়ী, .NET uses:

> “A generational, mark-and-compact garbage collector.”

মানে GC হলো 👉 **Generational + Mark–Sweep–Compact Hybrid**  
এটাই কারণ .NET-এর performance steady থাকে এবং developer-দের manual memory management দরকার হয় না।

## 🧾 Summary Recap

| Concept           | Explanation                                                         |
| ----------------- | ------------------------------------------------------------------- |
| **GC Trigger**    | Memory pressure, low memory, or manual call                         |
| **Mark Phase**    | Reachable object mark করা                                           |
| **Sweep Phase**   | Unused object free করা                                              |
| **Compact Phase** | Heap defragment করা                                                 |
| **Algorithm**     | Generational + Mark–Compact                                         |
| **Main Benefit**  | No manual memory management, less fragmentation, better performance |
