# ⚠️ উন্নতির জায়গা (Why Pruning Needed)

### 🔹 Sol v1

```java 
for(int i = crntNumber; i <= n; i++)
```

এখানে কোনো pruning নেই।

মানে —  
যদি বাকি সংখ্যাগুলো দিয়ে `k` পূরণ করা সম্ভব না হয়,  
তবুও recursion চলতে থাকবে।

---

# 🧠 আমরা আসলে কী করছি (High-Level Thinking)

App v1-এ আমরা 1 থেকে n পর্যন্ত প্রতিটি সংখ্যা দিয়ে tree generate করছি।

কিন্তু বাস্তবে —  
সব সংখ্যা থেকে valid combination তৈরি সম্ভব না।

---

## 📌 Example

```io
n = 4
k = 2
```

প্রথম লেভেলে যদি আমরা `4` থেকে tree generate করি —

তাহলে:

- আমরা 4 নিয়েছি
    
- এখন আরও 1টি সংখ্যা দরকার
    
- কিন্তু 4-এর পরে আর কোনো সংখ্যা নেই


👉 তাই 4 দিয়ে শুরু করলে কোনো valid combination সম্ভব না।

এমন branch-এ ঢোকা মানেই unnecessary recursion।

এই ধরনের অসম্পূর্ণ branch বাদ দেওয়াই হলো **pruning**।

---

# 🔍 Core Observation

Combination problem-এ আমরা:

- সিরিয়ালি এগোই (increasing order)
    
- পেছনে যাই না
    
- element reuse করি না
    

তাই একবার কোনো index থেকে শুরু করলে  
তার পরের available সংখ্যাগুলোই আমাদের resource।

---

# 🧮 Feasibility Logic

ধরো আমরা এখন index `i` তে আছি।

তাহলে:

```java
 Remaining needed  = rstk
 Available numbers = (n - i + 1)
```

Valid branch হওয়ার জন্য দরকার:

```java
Available numbers ≥ Remaining needed
```

অর্থাৎ,

```java 
n - i + 1 ≥ rstk
```

Solve করলে পাই:

```java
i ≤ n - rstk + 1
```

---

# 🎯 Final Optimized Loop

```java
for(int i = crntNumber; i <= n - rstk + 1; i++)
```

---

# 🧠 Intuition in One Line

আমরা শেষের দিক থেকে ঠিক `rstk` টা সংখ্যা “হাতে রেখে দিচ্ছি”  
যাতে combination complete করা সম্ভব হয়।

কিন্তু এমন জায়গা থেকে শুরু করছি না  
যেখান থেকে শেষ করা অসম্ভব।
