# 🪐 Sliding Window Pattern

---

## ➤ What is Sliding Window?

Sliding Window is a **pattern for efficiently solving problems involving contiguous subarrays or substrings** in linear structures (arrays, strings).

🔍 **Core Idea:**
Instead of re-scanning the same elements repeatedly, you **"slide" a window over the data**, updating your result in **O(1)** as elements enter/leave the window.

Think of it as **looking through a moving magnifying glass:**  
As you move, update only what enters/leaves your view without re-checking everything.

---

## ➤ The Three Fundamentals

1️⃣ **Window Definition**  
- Fixed-size window: Length `k`.  
- Dynamic-size window: Grows/shrinks based on constraints.

2️⃣ **Window Movement**  
- Expand: Move the **right pointer** forward.  
- Shrink: Move the **left pointer** when conditions are exceeded.  
- Track contents using counters, sets, or hash maps.

3️⃣ **Result Update**  
- Update the answer:
-  After each step (e.g., all windows).
-  Only when conditions are met (e.g., min/max length).

## ➤ Sliding Window Patterns to Master

✅ **Patterns:**
- Fixed window size: Process exactly `k` elements.
- Dynamic window size: Expand/shrink based on constraints (unique chars, at most X types, sum > target).
- Window + HashMap/Set: For tracking counts/frequencies.
- Monotonic Queue/Window: For max/min in a sliding window.

---

## ➤ How to Avoid Mistakes?

✅ **Tips:**
- 🚫 **Don’t brute-force:** Use sliding window if the problem mentions:
  - "subarrays", "substrings", "contiguous", "at most k types".
  
- ⚠️ Update window boundaries carefully to avoid **off-by-one errors**.
- 📊 Use counters/maps for dynamic constraints:
  - Especially for tracking unique elements or frequencies.
  
- 📝 **Dry-run with examples:**
  - Walk through by hand to ensure correct pointer movement.
