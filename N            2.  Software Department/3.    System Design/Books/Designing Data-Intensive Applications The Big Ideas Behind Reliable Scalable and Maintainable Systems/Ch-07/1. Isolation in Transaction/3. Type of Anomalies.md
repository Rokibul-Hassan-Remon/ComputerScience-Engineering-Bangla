## 📘 Transaction Isolation এ ঘটে যাওয়া Anomalies

### ✅ Anomalies প্রধানত দুই ভাগে ভাগ করা যায়:

|📚 ধরন|🎯 ব্যাখ্যা|
|---|---|
|🟦 **Read Anomalies**|যখন এক বা একাধিক transaction এমন ডেটা **read** করে যা **পরিবর্তিত, অপরিবর্তিত বা অপ্রত্যাশিত**|
|🟥 **Write Anomalies**|যখন এক বা একাধিক transaction এমনভাবে **write** করে যাতে **data corruption বা inconsistency** হয়|

---

## 🔎 🟦 Read Anomalies

|Anomaly|ব্যাখ্যা|উদাহরণ|
|---|---|---|
|**Dirty Read**|একটি transaction এমন ডেটা read করে যা আরেকটি transaction এখনও commit করেনি|T1 update করে, T2 সেটা দেখে ফেলে, কিন্তু T1 rollback করে|
|**Non-repeatable Read**|একই row বারবার read করলে আলাদা value পাওয়া যায়|T2 প্রথমবার পড়ে, T1 modify করে, T2 আবার পড়ে → value ভিন্ন|
|**Phantom Read**|একই query চালালে নতুন row পাওয়া যায়|T2 query চালায়, T1 নতুন row insert করে, T2 আবার চালায় → নতুন row দেখা যায়|

---

## 🛠️ 🟥 Write Anomalies

|Anomaly|ব্যাখ্যা|উদাহরণ|
|---|---|---|
|**Dirty Write**|দুইটি transaction একই ডেটা **একসাথে update** করে, এবং একটির rollback অন্যটির ফলাফল নষ্ট করে|T1 ও T2 একই row update করে, T1 rollback করলে T2-এর update হারিয়ে যায়|
|**Lost Update**|দুইটি transaction একই ডেটা পড়ে update করে, কিন্তু একটির লেখা আরেকটির উপর overwrite হয়ে যায়|T1 এবং T2 salary পড়ল, update করল → T2 এর লেখা হারিয়ে যায়|
|**Write Skew**|দুইটি transaction একই condition check করে আলাদা row update করে, ফলাফল ভুল state|Alice ও Bob দুজনেই on-call আছে দেখে off হয়ে যায় → শেষে কেউই on-call না|

---

## 📝 সংক্ষিপ্ত চেকলিস্ট:

|Anomaly|টাইপ|কি হতে পারে|
|---|---|---|
|Dirty Read|Read|Uncommitted data দেখা যায়|
|Non-repeatable Read|Read|বারবার read এ আলাদা ফলাফল|
|Phantom Read|Read|নতুন row হঠাৎ চলে আসে|
|Dirty Write|Write|একটির rollback অন্যটির লেখাও নষ্ট করে|
|Lost Update|Write|একটির লেখা overwrite হয়ে যায়|
|Write Skew|Write|একাধিক transaction ভুল সিদ্ধান্ত নেয়|
## 🎯 Bottom Line:

> Isolation Level ঠিক করার সময় আমাদের বুঝতে হয় ➤  
> আমরা কোন কোন anomaly **সহ্য করতে পারি**, আর কোনটা **করতে পারি না**।
