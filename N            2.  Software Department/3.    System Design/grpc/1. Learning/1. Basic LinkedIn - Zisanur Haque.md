আজকে একটু প্রোফেশন রিলেটেড টেকনিক্যাল পোষ্ট করি 😅  
  
আজকে জানার চেষ্টা করব gRPC আর tRPC আসলে কী?  
  
দুটোই মূলত Backend to Backend / Frontend to Backend যোগাযোগের আধুনিক পদ্ধতি, কিন্তু ব্যবহার ক্ষেত্র ও দর্শন আলাদা।  
  
gRPC কী?  
gRPC = Google এর তৈরি করা high performance RPC framework  
  
সহজভাবে,  
REST API যেখানে JSON পাঠায়,  
gRPC সেখানে binary data (Protocol Buffers) পাঠায় অনেক দ্রুত।  
  
gRPC কীভাবে কাজ করে?  
HTTP/2 ব্যবহার করে  
Request/Response ছাড়াও streaming সাপোর্ট করে, Strongly typed (schema আগে define করতে হয়)  
  
gRPC কোথায় বেশি ব্যবহার হয়?  
Microservices architecture  
High scale systems (Google, Netflix type infra)  
Backend to Backend communication এ  
  
gRPC এর সুবিধা,  
খুব fast  
ছোট payload  
Strict contract (breaking change কম)  
  
gRPC এর অসুবিধা,  
Browser friendly না (extra proxy লাগে)  
শেখা একটু কঠিন  
Simple CRUD app এর জন্য overkill হতে পারে  
  
tRPC কী?  
tRPC = TypeScript centric RPC framework  
  
সহজভাবে,  
Frontend থেকে Backend function কল করা,  
কোনো API schema / Swagger / DTO না লিখেই।  
  
tRPCকীভাবে কাজ করে?  
End to end Type Safety  
Backend function থেকে Frontend-এ direct usable, REST বা GraphQL না লিখেও API বানানো যায়  
  
tRPC কোথায় বেশি ব্যবহার হয়?  
Full stack TypeScript app  
Next.js / React + Node backend  
Startup / SaaS / Rapid development  
  
tRPC এর সুবিধা,  
Zero API boilerplate  
Compile time-এই error ধরা পড়ে  
Frontend dev experience অসাধারণ  
  
tRPC এর অসুবিধা,  
TypeScript ecosystem-এর বাইরে তেমন কাজের না  
Public API / mobile / external client-এর জন্য ideal না  
  
gRPC vs tRPC Comparison  
  
Primary use:  
gRPC - Service to Service  
tRPC - Frontend to Backend  
  
Data format:  
gRPC - Protobuf (Binary)  
tRPC - JSON (Typed)  
  
Language:  
gRPC - Multi-language  
tRPC - TypeScript only  
  
Performance:  
gRPC - Extremely high  
tRPC - Good  
  
Learning curve:  
gRPC - Medium to Hard  
tRPC - Easy  
  
Browser support:  
gRPC - N/A (extra setup)  
tRPC - Yes
