
# 1️⃣ Container কী?

Container হল **lightweight, isolated, portable application environment**  
যেখানে Application + Dependency একসাথে package করে run করা হয়।

👉 Container **OS share করে**, Kernel share করে  
👉 শুধু App-level isolation দেয়  
👉 তাই VM এর মত heavy নয়

---

# 2️⃣ Container যে সমস্যাগুলো solve করেছে

## 🔥 Problem-1: “মেশিনে আমার app চলছে, কিন্তু সার্ভারে চলছে না”

Developer machine vs Production server environment mismatch  
→ Library difference  
→ OS version mismatch  
→ Dependency conflict

✔ Container ensures **same environment everywhere**  
(“Works on my machine” problem gone)

---

## 🔥 Problem-2: VM is too heavy

**VM needs:**

- Full OS
    
- `Own kernel`
    
- `GB-sized images`
    
- `Minutes to boot`
    

**Container**:

- `MB-level image`
    
- `Boot in milliseconds`
    
- `OS share করে`
    

✔ Perfect for microservices

---

## 🔥 Problem-3: Deployment too slow

**Earlier**:

- Manual setup
    
- `Config conflict`
    
- `Slow update`
    

**Container**:

- Just replace image
    
- `Immutable infrastructure`
    
- `Super fast deploy`
    

---

## 🔥 Problem-4: Scaling difficult

VM scaling = heavy, slow, costly  
Container scaling = fast, lightweight, automated

✔ Modern cloud-native scaling possible (Kubernetes)

# 3️⃣ Container-এর Evolution / History

### ⭐ 1979 – UNIX chroot

প্রথমবার process কে তার own directory jail-এ আটকে রাখা হয়  
→ isolation এর শুরু

### ⭐ 2000–2004 – FreeBSD Jail, Solaris Zones

Stronger container-like isolation

### ⭐ 2007–2008 – LXC (Linux Containers)

Linux kernel features:

- `cgroups`
    
- `namespaces`  
    এই দুই মিলেই modern container-এর base তৈরি হয়।
    

### ⭐ 2013 – Docker Revolution

Docker introduce করে:

- Image
    
- Layered filesystem
    
- Registry
    
- Portable packaging
    

এটাই container-এর mass adoption কে possible করে।

### ⭐ 2014–2018 – Kubernetes

Large-scale container orchestration standard হয়ে যায়।

# 4️⃣ Container কীভাবে কাজ করে (Internal Mechanics)

Container relies on **Linux kernel features**:

### 🔹 namespaces → Process isolation

Each container thinks:

- its own filesystem
    
- own network
    
- own PID
    
- own user space
    
- own mount points
    

### 🔹 cgroups → Resource control

Control:

- CPU
    
- RAM
    
- I/O
    
- Network
    

### 🔹 UnionFS / OverlayFS → Layered filesystem

Image = multiple layers  
→ Reuse possible  
→ Lightweight  
→ Fast build

### 🔹 Container Runtime

Examples:

- Docker Engine
    
- containerd
    
- CRI-O
    

Runtime container create করে, manage করে।

---

# 5️⃣ Container Image Concepts (Important)

Image হল:

- Read-only
    
- Layered
    
- Versioned
    
- Portable
    

Container = image + small writable layer

📌 OCI Standard  
All modern container images follow OCI (Open Container Initiative)

---

# 6️⃣ Containers vs VM (Deep comparison)

|Feature|Container|Virtual Machine|
|---|---|---|
|OS|Shared|Separate OS|
|Kernel|Shared|Own kernel|
|Size|MB|GB|
|Boot Time|ms|seconds-minutes|
|Isolation|Process-level|Hardware-level|
|Performance|Near-native|Slight overhead|
|Use Case|Microservices|Full OS needed apps|

---

# 7️⃣ Container Architecture (High-level)

Bare Metal  
→ OS  
→ Container Runtime (Docker/containerd)  
→ Containers

Or through Hypervisor:  
Bare Metal → Hypervisor → VM → OS → Runtime → Containers

# 🔟 Container Security (Important Details)

### Threat:

- Shared kernel → risky
    

### Mitigation:

- seccomp
    
- SELinux / AppArmor
    
- user namespaces
    
- non-root containers
    
- image signing
    
- vulnerability scanning
